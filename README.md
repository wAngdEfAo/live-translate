# 实时翻译 / Live Translate

Android 屏幕实时翻译：把屏幕上显示的外文**就地**换成中文或英文，只覆盖文字区域，空白与图片不受影响。

## 功能

- 悬浮覆盖式显示：在原文位置用不透明色块盖住原文并显示译文，字号与原文一致
- 只处理屏幕上的一段区域（默认顶部 60%，可拖动分界线调整比例、也能切成从下往上）
- 拖动控制条、上下拖分界线调整处理区域、查看最近 3 条历史
- 完全离线：ML Kit 本地模型，下载后无需联网
- **58 种语言 → 中文，58 种语言 → 英文**（共 59 种语言可选，各自排除目标语言自己）
- 中文 ↔ 英文直连；其他语言经英语中转（如 日语→中文 = 日→英→中），速度略慢
- 缺模型时**不会**在后台自动下载，请在语言列表里手动点「下载」（体积与耗时都写在界面上）
- **可选高精度引擎**：OPUS-MT（Marian）int8 模型，英⇄中双向，句子更通顺；模型包约 294MB，需单独导入
- 自动检测源语言：识别池覆盖全部 59 种，自动检测 → 中文 / → 英文 两个独立入口
- 语言包可导出/导入 zip，换机免重新下载
- 隐私：译文只留在内存，不写盘、不上传

## 安装

1. 下载 Release 页里的 `live-translate-vX.Y-release.apk`（或自行编译）
2. 允许未知来源安装
3. 按 App 内三步引导：无障碍权限 → 悬浮窗权限 → 下载语言包


授权后可在 App 内一键开关无障碍，且不会影响其他无障碍服务。

## 编译

环境要求：

- JDK 17
- Android SDK：platform 36、build-tools 36.0.0
- Gradle 8.11.1

```bash
echo "sdk.dir=/path/to/Android/Sdk" > local.properties
./gradlew assembleDebug     # 调试包：不混淆，产物与源码一一对应
./gradlew assembleRelease   # 正式签名包：需 keystore.properties
```

签名配置放在 `keystore.properties`（**不在仓库中**，已在 .gitignore 忽略）：

```properties
storeFile=/absolute/path/to/your.jks
storePassword=你的密钥库密码
keyAlias=你的别名
keyPassword=你的密钥密码
```

缺少该文件时 release 以未签名方式产出，需自行签名后分发。

> arm64 Linux 主机若缺少可用 aapt2，可在 `gradle.properties` 中通过
> `android.aapt2FromMavenOverride` 指向本地 aapt2 路径。

> Windows 上项目路径不能含非 ASCII 字符：AGP 会直接拒绝构建
> （`Your project path contains non-ASCII characters`）。请放在纯英文路径下。

## 实现要点

| 模块 | 作用 |
|---|---|
| `ScreenReaderService` | 无障碍服务，读取屏幕文本节点及其矩形 |
| `OcrService` | 按需截屏 + ML Kit OCR，补齐节点拿不到的文字与背景取色 |
| `TextPipeline` | 过滤非目标语言文本，判断矩形是否可靠 |
| `Translator` / `LanguagePack` / `TransEngine` | ML Kit 离线翻译封装、缓存与模型管理；`TransEngine` 是引擎抽象，`MlKitEngine` 是默认实现 |
| `OnnxEngine` / `MarianTokenizer` / `EnginePack` | 高精度引擎：ONNX Runtime 推理、纯 Kotlin 的 Marian 分词、模型包导入导出 |
| `OverlayService` | 覆盖层渲染、手势、历史、控制条、前台常驻 |
| `MainActivity` | 权限引导、语言包管理、引擎与存储管理 |

## 高精度引擎（可选）

默认引擎仍是 ML Kit：快、支持 59 种语言、离线。另有一条可选的高精度路径，
用 [OPUS-MT](https://huggingface.co/Helsinki-NLP)（Marian，6 层，74M 参数）的 int8 ONNX 模型，
只做**英→中 / 中→英**两个方向，长句明显比 ML Kit 通顺，代价是慢。

- 模型不进 APK：单方向 encoder 53MB + decoder 93MB ≈ 148MB，双向合计约 294MB
- 装法：`高精度引擎 → 下载模型包`（App 内直接下，仅 Wi-Fi 可关），或自己下载 zip 后 `导入 zip`
- 换机前可 `导出` 成 zip，再在新机导入
- 地址失效时：长按「下载模型包」复制地址，用浏览器下载后走 `导入 zip`
- 默认只在**长句**（≥24 字符）上用高精度，短 UI 文案仍走 ML Kit；可在界面关掉这个限制
- 没装模型、语言对不是英⇄中、文本短于阈值或长于 400 字符时，`Engines.pick` 直接选 ML Kit；
  **推理失败（模型损坏 / 会话加载不出来 / 超时）会自动用 ML Kit 重试那一段**，不会留空
- 长于 400 字符的段落不走高精度：无 KV cache 的解码是 O(n²)，长段落必然超预算

模型与推理链路的实测数据（桌面 CPU，4 线程，无 KV cache）：

| 指标 | 结果 |
|---|---|
| 单方向体积 | encoder 52.9MB + decoder 93.4MB（fp32 为 210MB + 369MB） |
| 单句延迟 | p50 30ms（英→中）/ 36ms（中→英），96 token 上限 |
| 与 fp32 PyTorch 参考的一致性 | 英→中 12/20 完全相同，其余为同义改写；中→英 8/10 |
| 分词一致性 | 与真实 `MarianTokenizer` 逐 id 对比 31/31 一致（见 `MarianTokenizerTest`） |

模型许可证 CC-BY 4.0（Helsinki-NLP）。推理用 `onnxruntime-android`，因此 APK 比纯 ML Kit 版大约多 11MB。

## 安全与隐私

本项目**不做任何数据上传**。逐条说明权限用途：

| 权限 | 用途 | 何时触发 |
|---|---|---|
| 无障碍服务 | 读取当前屏幕上的文字与其位置 | 屏幕内容变化且翻译开关开启时 |
| 悬浮窗 | 在原文位置绘制译文覆盖层 | 显示译文时 |
| 屏幕捕获（可选） | 无障碍读不到文字时截图做 OCR 兜底、并采样背景色 | 无障碍读不到时；开了「精准模式」则每次内容变化都截 |
| 前台服务 | 保持悬浮层与截屏服务存活 | 悬浮窗开启期间 |
| 通知 | 显示前台服务状态 | 常驻通知，可关闭 |

### 关于 `WRITE_SECURE_SETTINGS`

上面那条 `pm grant` 授权之后，App 才有能力自己改写系统的无障碍开关（「一键开关」就是这么实现的）。

代价要说清楚：**这等于把设备上所有无障碍服务的控制权交给这个 App**——任何持有该权限的进程都能开启或关闭别人安装的无障碍服务。
如果不需要一键开关，**不要执行这条命令**，照常用系统设置手动开启无障碍，功能完全一样。

### 语言包导出 zip 里有什么

导出会把 App 私有目录下的三类内容打成一个 zip：

- `files/`——App 自己的配置与运行期文件
- `nobackup/`——ML Kit 模型目录（`com.google.mlkit.translate.models/dict.*/`），换机免下载的关键
- `cache/`——临时文件

**不包含** `shared_prefs/`：ML Kit 的模型登记状态不打包，导入时由 App 按模型目录重新补写。
也不包含任何屏幕内容、原文或译文。

数据流向：

- 翻译全程在**本地模型**完成，屏幕内容不出设备
- 译文只存在于内存，最多保留最近 3 条，不写磁盘
- 无广告、无统计 SDK、无第三方上报
- 唯一的网络请求是首次下载语言包（也可用导入 zip 离线完成）

可自行验证：源码 MIT 公开、debug 构建不混淆，可自行编译后与本 Release APK 比对代码行为。

## 已知限制

- 银行、支付类 App 常屏蔽无障碍节点，只能依赖 OCR
- 覆盖不到状态栏 / 通知栏
- 部分国产 ROM 会回收无障碍服务，需要手动重新开启
- 覆盖层不会阻止系统熄屏（未加 `FLAG_KEEP_SCREEN_ON`，优先省电）
- 密码 / 验证码输入框不会翻译（无障碍侧按 `isPassword` 跳过，OCR 侧跳过圆点/星号行）
- 非英语语言翻中文要经英语中转，需要两个模型（约 70MB），延迟约为直连的两倍
- 「自动检测」仍在测试阶段：短文本、混排文本的识别可能出错，导致翻译不准确或耗时变长
- 使用自签名证书发布，首次安装需允许「未知来源」

## 版本历史

### 5.5.9
- 修「释放后立刻重载」：`releaseUnderPressure()` 置 60 秒 `noLoadUntil`，`ensureLoaded`
  命中就直接报错让调用方回退 ML Kit。之前释放完，队列里下一个任务立刻重新读 146MB，
  内存最紧张的时刻反而多一次读盘与分配（`LMK` 下可能直接被 OOM）
- `sweepOrphans()` 走 `importZip` 同一把锁，`.old-*` 也加 30 分钟年龄门：
  启动清理不会再插进「改名成 .old-X」与「回滚/删除」之间把回滚目录删掉
- `translate()` 里每块的 `EnginePack.isInstalled`（3 次 stat + 清单查表）改为 5 秒 TTL 缓存
- 「安全窗口」提示文案改保守：「这一屏没有可识别的文字（可能是禁止截屏的界面）」——
  判据本质是"接近纯黑且 OCR 无输出"，深灰安全内容（如 #1A1A1A）判不出，OLED 黑画面又会命中

### 5.5.8
- 修高精度冷却误伤：只有**等到超时**才进 2 分钟冷却；会话被内存压力关掉、模型被删、
  加载失败这些错误路径不再让接下来两分钟的长句静默降级（5.5.7 的 `releaseUnderPressure`
  正好会踩到）
- 修内存压力释放失效：释放请求原来排在 FIFO 单线程队尾，积压推理跑完前 `active` 一直 >0，
  内存最紧、队列最长时反而释放不掉。现在解码每步检查 `releasePending` 并提前中断，
  让任务快速退出后立刻关会话
- `.old-*` 残留目录改为启动时也清一次（原来只在导入时清，进程中断后 147MB 一直挂着）
- `sweepOrphans()` 不再动 30 分钟内还在使用的 `.staging-*`；`importZip` 加锁，
  UI 导入与下载后导入不会互删临时目录
- 安全窗口判据收紧到「极差 ≤4 且亮度 ≤10」：深色主题空笔记页（#121212）与全屏深色视频
  不再被误报成「禁止截屏」
- `transSummaryBase` 在切屏时清空
- 文档修正：截断退避的"连续两次起 5 秒"只在同一屏（指纹不变）成立，滚动会重新按 1.2 秒算
- 已知（可接受）：超时被放弃的推理仍会跑完并写缓存，冷却期间的译文会与冷却后不一致

### 5.5.7
- 修 `REUSE_ID(-2)` 与各处 `id < 0` / `>= 0` 判断冲突：本地已有完整包时被当成"没有地址"直接返回，
  白修了一轮。现在判 `== NO_TASK`；复用情况直接转校验导入；三处恢复轮询的门槛改 `!= NO_TASK`
- 修 `engineDlBytes` 不复位：新任务开始时清零，否则 `grew` 全程 false，仅 Wi-Fi 守卫整段失效
- 修截断重试**每轮从第 0 块重来**：高精度超时的句子进 2 分钟冷却，下一轮直接走 ML Kit，
  不再每轮白等 6 秒再回退
- 修安全窗口误报：判定改为「中间 80% 区域纯色 **且** 整体很暗（≤48）」，
  纯白/浅色空白页不再被当成禁止截屏
- 修 `releaseUnderPressure()` 在 `active==0` 时从主线程直接关会话（仍有竞态）：
  统一置标记并向推理线程投空任务，只在它的空闲边界关
- 导入时清理上次替换中断留下的 `packs/<key>.old-<ts>`（147MB，会被算进占用与导出包）
- 修首页摘要拼出「（已装 1 个方向）（已装 1 个方向）」：加基础文本比对，旧结果不再覆盖新一轮
- `truncStreak` 按屏幕隔离，换屏不再继承上一屏的 5 秒退避级别
- `onCreate` 不再额外 `refresh()`（`onResume` 紧随其后），少起两轮后台线程

### 5.5.6
- 修「仅 Wi-Fi 下载」在非 Wi-Fi 下**误删已下载进度**：`lastDlBytes` 存进偏好，
  且要求「本次会话内确实观察到增长」才判定，recreate/旋转/回前台不再把首帧当成增长
  而 cancel（`DownloadManager.remove()` 会连带删掉已下载数据）
- 显式声明 `ACCESS_NETWORK_STATE`（之前靠 `mlkit:translate` 的 manifest 合并进来，太脆）
- 修「截断后无限重跑」：partial 记 `#part:N` 并退避（第 1 次 1.2 秒、连续两次起 5 秒），
  不再以 300–600ms 的节奏反复灌爆 ONNX 队列
- 修 `releaseUnderPressure()` 在推理进行中从主线程关会话（ORT 的 close/run 无并发保证，
  可能 use-after-free 崩溃）：改为置标记，等推理线程自己退出后再关
- 修 `ensureLoaded` 在 decoder 建会话失败时漏掉已建的 encoder（每次重试漏 53MB 原生内存）
- 修下载状态机无终止态：导入失败/任务消失时清 `engineDlId`，不再每次回前台重跑一遍
  294MB 的 sha256
- 下载前若本地已有完整文件，直接复用并导入，不再删掉重下
- WebView 类界面「拿不到根节点」不再计入退避，避免 5 秒才抓一帧
- 安全窗口判定改为「中间 80% 区域纯色 **且** OCR 读不出东西」，不再误判纯白空白页
- 首页状态摘要里的 `EnginePack.installed()` 移到后台线程，不再在 onResume 同步做磁盘 IO
- 子页状态与自测输入在 recreate/旋转后恢复，不再被踢回首页
- 引擎判定改为整屏一次快照（`Engines.reach()`），逐块只做内存判断
- `MarianTokenizer` 的 `decoder_start` 缺省值改为按 `pad` 推导（不再硬编码 65000）
- ONNX 去重表加 32 条上限，避免滚动时无限增长

  收进「更多设置」折叠区；高精度引擎的自测框与下载选项收进卡内「高级」折叠；

### 5.4.2
- **模型包可以在 App 内下载了**：之前只能自己找浏览器下载再「导入 zip」。现在
  「高精度引擎 → 下载模型包」走系统 DownloadManager（断点续传、通知栏进度、仅 Wi-Fi），
  下完自动校验整体 sha256 → 导入 → 删掉那个 294MB 的 zip；地址失效时长按按钮可复制地址手工导入
- **微信 / 内嵌 WebView 类界面不再静默不翻**：`rootInActiveWindow` 返回 null 时以前直接 return，
  连「无障碍读不到就走 OCR」这个判断都到不了。现在会交空列表下去触发 OCR 兜底；
  另补 `typeWindowsChanged` / `typeViewTextChanged` 两类事件；OCR 不可用时提示一次该开哪个开关
- **安全窗口能识别**：截屏是一整片纯色（FLAG_SECURE）时不再白跑 OCR，并提示一次「当前界面禁止截屏」
- **横屏后控制条/分界线跑到屏幕外**：控制条位置改存比例（跨方向自洽），旋转/分屏时重新夹进屏幕；
  旧版本留下的绝对坐标会按当前屏换算一次；分界线上下都夹

### 5.4.1
- **修复 release 包会崩溃的问题**：`onnxruntime-android` 的 AAR 不带 consumer proguard 规则，
  R8 把 `ai.onnxruntime.OrtException` 等类改名，而 JNI 按名字查找（`libonnxruntime4j_jni.so`
  里有 444 个 `Java_ai_onnxruntime_*` 符号）→ 一进错误路径就 `NoClassDefFoundError`。
  已加 `-keep class ai.onnxruntime.**`，并在 mapping 与 dex 里逐类核对
- 修复 `effSrc` 把所有源语言的纯拉丁行都当英语：目标=中文时法语/西语/德语行被送进 en→zh
  （绕过 X→en→目标），目标=英文时更是直接跳过不翻。现在只对日/韩生效
- 高精度推理失败自动回退 ML Kit 重试（之前只是留空，与文档不符）
- 截断保护：整屏预算用尽时不再把整屏指纹记成「已处理」，后半屏会在下次事件继续翻
- ONNX 队列同句去重；`SessionOptions` 用后关闭（每次重载都漏）；内存压力下强制释放会话
  （之前 `active>0` 时 release 只是重排定时器，等于没释放）；空闲释放不再清文本缓存
- 超过 400 字符的块不走高精度；解码加退化保护（同 token 连发 6 次即收尾）
- 模型包导入改为「解到临时目录 → 校验清单 size + sha256 → 整体替换」，
  半截模型不会再被当成「已安装」；导入前检查剩余空间；兼容扁平 `en_zh/...` 布局
- 整屏只判一次引擎可用性，不再每块读 Prefs + stat 模型文件
- OCR 忙碌标记加回合号，迟到的旧回调不会清掉新一轮标记
- `decoder_start` 由模型的 pad id 推导（模板不再写死 65000）
- 分词器掩码改用「原文含私用区字符就跳过」，不会再把原文换掉
- 单测覆盖英⇄中两个方向（7 个用例），夹具与发布 zip 同源
